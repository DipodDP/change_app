# Change

[English](README.md) · Русский

Change подбирает самый выгодный способ обменять валюту по обменам, которые вы
уже совершили, а не по биржевым курсам.

Для каждого обмена вы записываете, сколько отдали, сколько получили и в каком
банке. По этим двум суммам получается фактический курс, в который уже входит
комиссия. Change считает каждый обмен ребром графа, находит все цепочки между
двумя валютами и сортирует их по тому, сколько вы получите в итоге.

## Пример

Допустим, записаны такие обмены:

| Отдали | Получили | Банк | |
|---|---|---|---|
| 60 000 RUB | 2 140.43 BYN | Белинвестбанк | |
| 100 BYN | 28.84 EUR | Приорбанк | |
| 28.84 EUR | 28.70 EUR | Приорбанк → OTP | перевод |
| 14.02 EUR | 5 000 HUF | OTP | |
| 100 BYN | 33.26 USD | Freedom | |
| 33.26 USD | 32.60 USD | Freedom → Wise | перевод |
| 7.34 USD | 2 200 HUF | Wise | |

Сравнение 100 BYN → HUF:

| Маршрут | Итог | |
|---|---|---|
| BYN → EUR → HUF, через Приорбанк и OTP | **10 235.38 HUF** | лучший курс |
| BYN → USD → HUF, через Freedom и Wise | 9 771.12 HUF | −4.54% |

Через евро выходит на 464.26 HUF больше с каждых 100 BYN. Маршрут RUB → HUF
вводить не нужно: Change сам построит его через BYN.

Цепочка продолжается только в том банке, где лежат деньги, потому что остаток
в одном банке нельзя потратить в другом. В примере деньги между банками
переносят две строки-перевода. Без них осталось бы семь несвязанных обменов и ни
одного маршрута. Внесение наличных записывается так же: как перевод в той же
валюте из «Наличные» в банк.

## Аккаунты

Пользоваться всем можно без входа. Обмены, записанные без входа, привязаны к
браузеру и хранятся, пока он заходит хотя бы раз в 30 дней. После регистрации
по почте и паролю они переходят в аккаунт. Там они хранятся бессрочно, и их
можно открыть с любого устройства.

## Запуск

Зависимостями управляет [uv](https://docs.astral.sh/uv/). `uv run` сам создаёт
и обновляет окружение, так что активировать его не нужно.

    uv run python manage.py migrate
    uv run python manage.py compilemessages -l ru -l en
    uv run python manage.py createsuperuser        # для /admin/
    uv run python manage.py runserver

Затем откройте http://127.0.0.1:8000. Скомпилированных файлов перевода в
репозитории нет, поэтому в списке есть `compilemessages`.

Чтобы открыть приложение в локальной сети или tailnet, слушайте все интерфейсы
и перечислите адреса машины в `.env`
(`DJANGO_ALLOWED_HOSTS=192.168.1.10,100.64.0.1`):

    uv run python manage.py runserver 0.0.0.0:8000

Обмены без входа остаются в базе и после истечения сессии, пока их не удалят.
Запускайте раз в день:

    uv run python manage.py clearsessions && uv run python manage.py purge_guests

## Развёртывание

Change устроен как обычный Django-проект на WSGI (`config.wsgi:application`) и
хранит данные в SQLite. Его можно запустить на любом хостинге с Python 3.12 или
новее.

**1. Получите код.**

    git clone https://github.com/DipodDP/change_app.git
    cd change_app

**2. Настройте.** Скопируйте файл-пример и впишите свой домен и секретный ключ.
Ключ можно сгенерировать командой
`python3 -c "import secrets; print(secrets.token_urlsafe(50))"`.

    cp .env.example .env && chmod 600 .env

Сайт, команды управления и запланированные задачи читают `.env`, поэтому
секретный ключ у них общий. Без этого ключа задача очистки не сможет прочитать
сессии. Если переменная задана и в самом окружении, используется её значение.
С `DJANGO_DEBUG=0` приложение не запустится, пока не задан настоящий ключ.

**3. Создайте virtualenv.** Выполните в папке проекта:

    uv sync --frozen --python 3.13

Команда создаёт `.venv/` ровно с теми версиями, что указаны в `uv.lock`.
Укажите эту папку WSGI-серверу (`/path/to/change_app/.venv`). Флаг `--python`
выбирает интерпретатор, если их на сервере несколько.

Если на сервере нет uv, установите его через `pip install --user uv`. Можно
обойтись и без него:

    python3.13 -m venv .venv && .venv/bin/pip install "django==6.1"

В этом случае следить, чтобы версия Django совпадала с `uv.lock`, придётся
самим.

**4. Подготовьте.**

    .venv/bin/python manage.py migrate
    .venv/bin/python manage.py compilemessages -l ru -l en
    .venv/bin/python manage.py collectstatic --noinput
    .venv/bin/python manage.py createsuperuser

Чтобы сохранить существующие данные, скопируйте свой `db.sqlite3` в папку
проекта до запуска `migrate`.

**5. Запустите.**

- Запустите `config.wsgi:application` тем WSGI-сервером, который есть у
  хостинга (Gunicorn, uWSGI, mod_wsgi или встроенный в платформу). Рабочей
  директорией укажите папку проекта, а Python возьмите из `.venv`.
- Папку `staticfiles/` отдавайте по адресу `/static/`.
- Работайте только по HTTPS и перенаправляйте на него обычный HTTP. С
  `DJANGO_DEBUG=0` cookie сессии и CSRF передаются только по HTTPS, поэтому по
  HTTP войти не получится.

**6. Запланируйте очистку** раз в день, например через cron:

    0 4 * * * cd /path/to/change_app && .venv/bin/python manage.py clearsessions && .venv/bin/python manage.py purge_guests

Если задача не может прочитать сессии, она останавливается и ничего не удаляет.

**Обновление** в дальнейшем:

    git pull && uv sync --frozen \
      && .venv/bin/python manage.py migrate \
      && .venv/bin/python manage.py compilemessages -l ru -l en \
      && .venv/bin/python manage.py collectstatic --noinput

Затем перезапустите WSGI-сервер.

## Заметки

- **Деньги** округляются до 2 знаков банковским округлением
  (`ROUND_HALF_EVEN`, см. `exchanges/money.py`). Курсы в расчётах не
  округляются, только при показе.
- **Курсы исторические.** Они взяты из уже совершённых обменов, поэтому
  показывают, какой путь был дешевле, а не сколько обмен стоит сейчас. В
  маршрутах участвует только последняя запись для каждой пары валют и банка.
  Более старые записи остаются в списке как история.
- **Маршруты** строятся поиском по графу всех записанных обменов. Маршрут не
  выходит за пределы банка, если деньги не перенесены переводом. Он может и
  заканчиваться переводом, поэтому «EUR наличными» и «EUR, внесённые в банк»
  показываются как разные варианты.
- **Языки**: английский и русский, переключаются в шапке.
